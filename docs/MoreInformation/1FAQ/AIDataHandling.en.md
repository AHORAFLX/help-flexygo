# Data handling in Flexygo AI

In Flexygo, AHORA's tool, advanced artificial intelligence systems have been implemented to optimize the management and retrieval of information. Among these, the RAG (Retrieval-Augmented Generation) and SQL Live Data systems stand out, both designed to enable smart interaction with the data stored in the tool. Both systems guarantee privacy and confidentiality, keeping the data under strict control within Flexygo's private environment.

## How the RAG system works

The RAG system in Flexygo lets you manage and query information from documents previously uploaded to the system through the following steps:

* **Document upload:** users upload documents directly into the Flexygo tool. Only PDF, TXT and DOCX (Word) documents are supported for processing through the RAG system.
* **Document vectorization:** documents are automatically split into manageable chunks (generally paragraphs). These specific chunks are sent individually to the OpenAI API, which converts the text into numeric vectors capable of capturing the semantic meaning of the text, making later similarity searches possible. It's worth noting that OpenAI does not have full or public access to the document, only to specific chunks.
* **Storage in SQL Server:** the vectorized chunks are stored exclusively in a SQL Server database owned by Flexygo, ensuring efficient and secure access.
* **Interaction through chat:** when queries are made in the chat, they are also vectorized through the OpenAI API. The system compares the vectorized query against the stored chunks, sending only the relevant chunks as specific context to generate the responses.

## How the SQL Live Data system works

The SQL Live Data system lets the chat generate responses from direct database queries using T-SQL statements generated by OpenAI. This works as follows:

* **Secure query generation:** the OpenAI API does not have real or direct access to the database. Instead, it creates specific T-SQL queries that are then executed in Flexygo.
* **Privacy in queries:** the queries generated by OpenAI are strictly read-only, making it impossible to modify the database. Only the specific, limited results of those queries are sent to the chat, guaranteeing privacy. These isolated results lack full context, which further increases data protection — for example, providing only an isolated value like "32" with no additional context. Users can also view the queries executed by the chat, ensuring transparency and trust in the process.

## OpenAI's privacy policy

All communication and data sent to the OpenAI API from Flexygo is carried out in accordance with [OpenAI's privacy policy](https://openai.com/en-US/policies/row-privacy-policy).
